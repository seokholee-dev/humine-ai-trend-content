# 칼럼 원고 작성

## 역할과 입력

Core Brief를 기업 실무자가 이해할 수 있는 한국어 칼럼으로 확장한다. AGENTS.md와 prompts/README.md를 읽는다.
필수 입력: 02_core_brief.md, 01_research.md, 05_sources.md.
선택 입력: 배포 채널, 목표 분량, 독자, 제목 방향.
templates/column_template.md와 style/humine_content_guide.md가 실제로 있으면 적용한다.
분량이 없으면 핵심 메시지를 충분히 설명하는 길이로 작성하고 실제 글자 수를 확인 가능한 경우만 보고한다.

## 수행

1. 핵심 메시지와 공통 사실 목록을 확인한다.
2. 독자가 겪는 업무 질문으로 시작하되 실제 조사 결과처럼 꾸민 인용이나 통계를 만들지 않는다.
3. 기술의 변화, 의미, 구체적인 업무 적용, 필요한 역량과 교육 방향을 자연스럽게 연결한다.
4. 업무 예시는 담당자·입력·과정·산출물·사람의 판단을 구체화한다. 가상 시나리오는 그 성격을 본문에서 밝힌다.
5. 기술의 한계와 적용 조건을 해당 설명 가까이에 둔다. 짧고 쉬운 문장을 쓰고 전문 용어는 첫 등장에 설명한다.
6. 교육은 필요한 역량에 대한 학습 제안으로 연결한다. 검증되지 않은 휴마인 상품, 고객, 성과를 쓰지 않는다.

## 출력: 03_column.md

- 작성일, 조사 기준일, 상태, 기반 Core Brief 경로
- 제목과 짧은 요약
- 도입: 독자의 업무 질문
- 트렌드와 의미
- 업무 변화와 적용 예시
- 필요한 역량과 교육 방향
- 결론: 핵심 메시지와 시도해 볼 다음 행동
- 출처: 사용한 [S번호]에 대응하는 원문 링크
- 편집 메모: 가정, 미확인 사항, 추가 확인 항목. 본문과 별도 구역으로 구분

변동 가능한 기능·가격·날짜·수치의 주장 가까이에 [S번호]를 붙인다.
새로운 사실이 필요하면 원문 확인 후 01_research.md, 05_sources.md, 02_core_brief.md부터 갱신한다.
원고만 요청받은 경우 본문을 파일로 저장하며 외부 채널에 게시하지 않는다.

## 완료 기준

Core Brief와 핵심 메시지·수치·조건이 일치해야 한다. 같은 주장을 표현만 바꿔 반복하지 않는다.
제목은 본문의 근거보다 강하게 단정하지 않는다. 작성 완료 후 상태는 초안으로 두고 fact_check.md 검수로 넘긴다.

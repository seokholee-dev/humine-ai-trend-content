# VS Code 대화에서 콘텐츠와 디자인 제작

공통 규칙은 루트 AGENTS.md, 단계별 지시는 prompts/README.md를 따른다. Python은 작업 준비·로컬 합성만 수행한다.

## 제작 순서

1. 주제·기간·형식을 확인하고 필요한 프롬프트·양식·스타일을 읽는다. 새 주제는 generate_content.py로 준비하고 기존 주제는 수정 내용을 보존하며 이어 쓴다.
2. 대화의 웹 도구로 원문을 확인하고 리서치·출처 → Core Brief → 요청된 원고를 작성한다. fact_check.md에 따라 사실·내용을 검수한다.
3. visual_planner.md에 따라 각 장의 메시지에 적합한 업무 장면·도식을 선택하고 `06_image_prompts.md`에 기획과 생성 프롬프트를 기록한다. 별도 JSON에 프롬프트를 중복 작성하지 않는다.
4. 이미지 생성까지 요청받았다면 imagegen 스킬과 내장 도구로 생성한다. 사용자의 세부 프롬프트를 기다리지 않고 구도·스타일을 설계한다. 메시지 전달, 피사체, 구도와 어색한 요소를 확인해 필요한 부분을 수정한다. 구체적인 이미지 기준은 visual_planner.md를 따른다.
5. 도구가 반환한 실제 파일을 `images/`에 저장하고 카드의 `이미지 경로` 또는 칼럼의 이미지 링크에 연결한다. 이전 자산은 보존하고 새 버전 파일명을 사용한다. 최종 프롬프트·실제 경로·대체 텍스트는 `06_image_prompts.md`에 기록한다.
6. 카드가 있으면 build_cardnews.py로 HTML을 합성한다. 최종 카드 PNG 요청 시 렌더링 환경을 확인하고 --png를 사용한다. 출력은 저장소 최상위 output/주제명/build-실행시각/에 모으고 기획 Markdown과 분리한다. 외부 출력 루트는 --output-root로 지정한다. 실행 명령은 scripts/README.md를 참조한다.
7. `07_review.md`에 사실·내용, 이미지 생성·저장, 합성, 시각 검수 상태를 기록한다. 각 원고 상단은 이 기록과 일치시킨다. 줄바꿈·넘침 검수는 기존 보류 상태를 유지한다.

## 도구 사용의 한계

내장 도구를 사용할 수 없거나 별도 과금이 필요한 경우 가능한 원고·기획·로컬 작업까지 진행하고 미완료 이유를 기록한다. 유료 API나 결제 서비스로 대체하지 않는다. 결과가 대화에만 표시되면 생성 완료와 저장·합성 미완료를 구분한다. 파일 경로를 추측하지 않는다.

# 시각 자료 및 공통 스타일 계획

## 역할과 입력

원고의 메시지를 이해하기 쉽게 만드는 이미지·도식·레이아웃을 계획한다. AGENTS.md와 prompts/README.md를 읽는다.
입력: 02_core_brief.md, 요청된 03_column.md 및/또는 04_cardnews.md, 05_sources.md.
선택 입력: 배포 채널, 출력 크기·비율, 브랜드 로고·글꼴·색상, 실제 사용할 제작 도구.
style/의 가이드와 CSS 파일이 있으면 먼저 확인한다. 없는 브랜드 자산이나 CSS 파일을 적용했다고 주장하지 않는다.

## 수행

1. 각 이미지의 설명 목적을 정한다. 장식만 필요한지, 비교·흐름·개념 설명이 필요한지 구분한다.
2. 실제 화면, 수치 차트, 개념도, 생성 일러스트를 구분한다. 실제 화면은 실제 자료를 사용하고 수치 차트는 검증된 데이터로 만든다.
3. 사진·일러스트용 생성 프롬프트와 최종 화면에 얹을 정확한 한국어 문구를 분리한다. 카드 전체의 텍스트와 레이아웃을 생성 이미지에 맡기지 않는다.
4. 카드뉴스의 공통 레이아웃과 예외가 필요한 장을 표시한다. 예외는 이유와 검수 항목을 남긴다.
5. 사용자가 실제 이미지 생성을 요청한 경우에만 도구로 생성하고 파일 존재를 확인한다. 기획 요청이면 제작 프롬프트까지 작성한다.

## 구체적인 이미지 기획과 수정

- 모든 장에 메시지를 설명하는 시각 자료와 독립 자산 ID를 배정한다. 장별 확보 방식은 공식 자료·사용자 제공 자료·재사용 가능한 이미지 확보 / 내장 이미지 생성 / 도식 직접 제작 중에서 고른다. 텍스트와 단색 배경만으로 시각 기획을 완료하지 않는다.
- 원문 이미지의 출처·제작자·재사용 조건을 확인하고 기록한다. 검색 썸네일을 그대로 가져오지 않는다. 조건이 불명확하거나 별도 과금이 필요하면 자체 제작 대안으로 바꾼다. 실제 화면을 자체 제작할 때는 제품 화면처럼 위장하지 않는다.
- 같은 배경을 여러 장에 반복하는 것을 기본으로 삼지 않는다. 재사용이 꼭 필요하면 메시지상 이유를 명시하며, 단순 색상·크롭 변경만으로 새 장면을 대신하지 않는다.
- 각 장에서 독자가 이해할 행동을 정하고 담당자·자료·행동·판단 지점을 장면으로 구체화한다. 추상적인 블록·빛·로봇을 기본 이미지로 반복하지 않는다.
- 표지는 핵심 장면, 업무 설명은 과정·비교 도식, 교육 장은 실습·체크리스트 등 메시지에 맞는 형식을 선택한다. 원고와 맞는 경우 자산을 재사용한다.
- 사진·일러스트는 내장 이미지 도구를 사용하고, 정확한 문구와 구조가 필요한 단순 도식은 HTML/CSS 등으로 구성한다. 실제 제품 화면과 수치는 원자료로만 표현한다.
- 참고 이미지가 있으면 스타일과 구도 기준으로 활용한다. 생성 후 메시지 전달·피사체·구도를 확인하고 어색한 부분을 수정한다. 실제 카드의 줄바꿈·넘침 검수와는 구분한다.
- 최종 사용한 프롬프트와 자산 경로는 06_image_prompts.md에 기록한다.

## padding·CSS 정규화 원칙

style/cardnews.css, style/humine_visual_guide.md와 style/layout-preview.html을 읽고 현재 구현값을 따른다. 현재 CSS가 없거나 접근 불가능하면 적용 완료로 보고하지 않는다.
사용자가 제공한 참고 이미지의 5종(cover, gradient, split, overlay, cta)을 재사용한다. 이미지보다 글자의 위치와 틀을 우선한다.

- 공통 값을 CSS 사용자 지정 속성(디자인 토큰) 한 곳에서 관리한다. 예: --card-padding, --space-1~8, --title-size, --body-size, --body-line-height, --radius-card. 실제 이름·값은 CSS를 기준으로 한다.
- 여백, 요소 간 gap, 글자 크기, 행간, 색상, 테두리와 모서리 값을 공통 토큰에서 참조한다.
- box-sizing, 기본 margin, 이미지 크기 처리와 글꼴 상속은 공통 초기화 규칙에서 관리한다.
- 공통 카드 구조는 header / body / footer로 구분한다. 바깥 padding, 출처 영역, 페이지 번호와 텍스트 안전 영역을 일관되게 유지한다.
- 장별 인라인 스타일이나 임의의 숫자 반복을 피한다. 명명된 레이아웃 변형과 공통 클래스가 우선이다.
- 출력용 고정 캔버스와 브라우저 미리보기 배율을 분리한다. 미리보기 크기 때문에 최종 이미지의 배치가 바뀌지 않게 한다.
- 본문이 넘치면 먼저 문구를 줄이거나 장을 나눈다. 기준 이하로 글자를 줄이거나 overflow를 숨겨 잘라내지 않는다.
- 현재 시안은 8px 간격 단위, 1080×1350 캔버스, 바깥 padding 80px, 제목 60px, 본문 40px을 사용한다. 표지·CTA의 크기 예외와 Y좌표는 CSS 토큰에서 관리한다. 공식 브랜드 확정값은 아니며 실제 원고와 글꼴로 검증한다.
- CSS로 정확한 여백을 제어하려면 HTML/CSS 렌더링 단계가 필요하다. 이미지 생성 프롬프트만으로 픽셀 단위 여백을 보장하지 않는다.

## 출력: 06_image_prompts.md

상단: 작성일, 조사 기준일, 상태, 입력 원고, 대상 규격, 적용 가이드·스타일 파일(실재하는 경로만), 미확정 항목.

각 자산 항목:
- 자산 ID와 연결된 카드 장/칼럼 위치
- 장별 확보 방식, 원문·재사용 조건 확인 상태, 확보 불가 시 대안
- 목적과 시각 자료 유형
- 구성, 정보 위계, 핵심 오브젝트
- 이미지 생성 프롬프트(해당 시): 주제·구도·톤·여백·제외 요소
- 별도로 배치할 정확한 텍스트
- 실제 화면·데이터·참고 자료의 출처 ID(해당 시)
- 레이아웃 변형, 사용할 공통 토큰, 예외 사유
- 파일명 계획, 대체 텍스트
- 제작 상태: 기획만 완료 / 생성 완료 / 검수 완료
- 실제 생성된 경로(생성 후에만 기입)

별도 섹션에 적용한 공통 스타일과 CSS 검수 항목을 정리한다.
검수 항목: 모든 장의 padding·gap 일치, 글꼴 로딩, 한글 줄바꿈, 넘침·잘림, 출처 가독성, 텍스트 대비, 최종 출력 크기.
렌더러와 실제 이미지가 없으면 시각 검수 미실시로 기록한다.

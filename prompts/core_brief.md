# Core Brief 작성

## 역할과 입력

리서치를 카드뉴스와 칼럼이 공유할 핵심 기획 요약으로 정리한다. 먼저 AGENTS.md와 prompts/README.md를 읽는다.
필수 입력: 같은 주제 폴더의 01_research.md, 05_sources.md. 선택 입력: 독자, 메시지 방향, 배포 목적.
templates/core_brief_template.md와 style/humine_content_guide.md가 실제로 있으면 함께 읽고 적용한다.

## 수행

1. 선정 주제와 핵심 근거를 확인한다. 후보만 있고 선정을 요청받았다면 리서치 기준으로 주제를 선정하고 근거를 기록한다.
2. 독자가 이 콘텐츠를 읽고 이해하거나 시도해야 할 변화를 한 문장으로 정한다.
3. 확인된 사실과 해석을 분리한다. 리서치에 없는 사실이 필요하면 먼저 원문을 확인하고 리서치·출처 목록을 함께 갱신한다.
4. Trend → Work → Skill → Education을 하나의 논리로 연결한다. 교육 방향은 업무 변화에 필요한 역량에서 도출한다.
5. 카드뉴스와 칼럼에서 유지해야 할 공통 주장·수치·조건을 지정하고, 형식마다 어떻게 설명할지 정리한다.

## 출력: 02_core_brief.md

- 작성일, 조사 기준일, 상태, 입력 파일
- 주제와 가제
- 대상 독자와 독자가 가진 업무 질문
- 한 문장 핵심 메시지
- Trend: 어떤 변화가 생겼는가? 주요 사실과 [S번호]
- Why now: 왜 지금 주목하는가? 발표 사실과 편집적 해석 구분
- Work: 업무 예시 1~3개. 담당자, 입력 자료, 기존 과정, 달라진 과정, 산출물, 사람의 검토 지점을 명시
- Skill: 각 업무 변화에 필요한 사람의 역량
- Education: 역량별 학습 목표와 실습 아이디어. 실제 운영 중인 휴마인 과정과 제안 과정을 구분
- 제한사항: 적용 조건, 기술 한계, 미확인 부분
- 형식별 전개: 칼럼 소제목 흐름, 카드뉴스 메시지 흐름
- 공통 사실 목록: 유지해야 할 주장·수치·조건·출처 ID
- 브랜드 연결: 근거 있는 휴마인 관점 또는 독자의 다음 행동. 상품 정보가 없으면 임의의 상품·성과·문의 링크를 쓰지 않음

## 완료 기준

모든 핵심 주장은 리서치와 일치해야 한다. 가상 업무 예시는 명확히 표시한다.
중요한 근거가 비어 있으면 검수 필요로 표시하고 후속 원고에서도 그 사실을 확정적으로 사용하지 않는다.
Core Brief가 바뀌면 이미 작성된 칼럼·카드뉴스의 관련 부분도 동기화한다.

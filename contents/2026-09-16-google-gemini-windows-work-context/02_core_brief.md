## 핵심 메시지
AI를 쉽게 부를 수 있게 된 만큼, 업무에 맞는 자료를 고르고 근거를 확인하는 역량을 함께 길러야 한다.

## 독자의 업무 질문
프로젝트 보고를 도울 AI에게 어떤 자료를 주고, 결과 중 무엇을 확인해야 할까?

## Trend와 Why
확인된 사실: Windows용 Gemini 발표와 단축키 호출 [S1]. Workspace 요약 활용과 관리 조건 [S2~S5]. 출시일은 9월 10일이며 9월 11일은 별도 Workspace 안내일이다.
휴마인의 해석: 별도 웹 창을 찾아가는 단계가 줄어드는 변화는 일상 업무 속 AI 활용을 생각하게 한다. 접근성이 높아졌다는 이유만으로 정확성이나 성과가 보장되지는 않는다.

## Work — 프로젝트 현황 정리
- 사례 구분: 가상 활용 예시, 제품 실계정 시험 아님.
- 담당자·입력: 프로젝트 담당자, 회사가 사용을 허용한 회의록과 상태 문서.
- 기존 과정: 자료를 찾아 읽고 결정·미결·요청 사항을 직접 정리.
- 제안 과정: 기간·자료 범위 지정 → 초안 요청 → 원문 대조 → 사람이 공유 판단.
- 산출물: 결정 사항·미결 사항·확인할 질문으로 구성한 현황 초안.
- 확인 지점: 최신 문서인지, 조건이 빠졌는지, 제안이 확정 사실로 바뀌었는지.
- 적용 조건: 조직의 사용 허용 범위와 연결 설정을 확인. 연결이 불가능하면 승인된 가상 자료로 연습.

## 공통 사실과 제한
S1~S5 외의 새 기능 주장을 추가하지 않는다. 자동 화면 읽기·모든 자료 접근·정확성·시간 절감 수치를 보장하지 않는다. 실제 사례는 제품 발표이며 업무 시나리오는 가상이다.

## 형식별 전개
칼럼: 출시 변화 → 주간 보고 사례 → 구체적 요청 → 일정 대조 → 역량과 동일 자료 실습 → 다음 보고에 적용.
카드: 칼럼의 동일 사례를 표지 → 호출 → 주간 보고 → 요청 예시 → 일정 대조 → 역량 → 실습 → 실행으로 재구성.

## 흐름 개정 기준
목요일(구버전)과 금요일(최신 결정)의 충돌은 가상 예시로 통일한다. 제안과 확정을 구분하는 설명은 칼럼에서 확장한다. 교육은 같은 자료 묶음에서 요청만 달리하는 비교 활동으로 이어간다. 제품 소개에서 곧바로 주의사항으로 넘어가지 않고 활용 장면을 먼저 보여준다.
